# CA.exe 调试器操作与逆向实战经验总结

> 本文档总结在通过调试器 (x64dbg MCP) 调试 `CA.exe` 客户端与服务端模拟器交互过程中的关键操作经验与逆向排查方法，供后续调试参考。

---

## 1. 调试器 (x64dbg MCP) 操作要点与避坑

### 1.1 `run` 命令的阻塞特性与状态判断
- **现象**：调用 `run` 后工具长时间无响应，3 分钟后提示超时被取消，但游戏窗口实际上已正常弹出并运行。
- **原因**：x64dbg MCP 的 `run` 会持续阻塞等待调试事件（如断点命中、未处理异常或程序暂停）。若目标程序没有遇到断点、处于流畅运行状态，`run` 命令就会一直等待。
- **正确做法**：
  1. 启动或恢复执行后，优先调用 `GetDebugState` 查看当前状态；
  2. 若返回 `status: RUNNING` 且 `isRunning: true`，说明游戏已在全速运行，**无需重复调用 `run`**；
  3. 需要检查内存或反汇编时，先调用 `PauseDebug` 暂停程序，检查完毕并清理断点后再调用 `run` 继续。

### 1.2 启动与 DLL/异常处理流程
从 EntryPoint (`0x7273FD`) 到主循环通常会经历以下暂停事件，依次使用 `run` 放行即可：
1. **系统断点 (System Breakpoint)**：位于 `ntdll`，点击 `run` 推进；
2. **模块加载 (DLL Load)**：如 `inputhost.dll`、显卡驱动 `amdxn32.dll` 等加载，点击 `run` 推进；
3. **线程命名异常 (`0x406D1388`)**：MSVC 内部机制，非崩溃，直接放行；
4. 进入主循环前调用 `DeleteAllBreakpoints`，确保无残留断点阻塞游戏渲染循环。

### 1.3 调试前环境检查
- **旧服务端常驻检查**：调试协议或修改包结构前，**必须先杀掉旧的 Java/服务端后台进程**，并用 `Get-NetTCPConnection -LocalPort 3838` 确认端口已释放并由新进程监听。否则客户端连入旧服务，会导致任何修改均不生效。

## 2. 客户端逆向排查方法

### 2.1 顺藤摸瓜：RTTI 虚表快速定位
`CA.exe` 保留了完整的 MSVC RTTI，分析类行为时切忌盲目单步，应优先定位虚表 (VTable)：
```python
# 1. 查找 TypeDescriptor
pos = data.find(b'.?AVCPrepareStage@@')
# 2. 匹配 CompleteObjectLocator，再匹配 VTable
# 3. 直接导出虚函数表 (OnPacket, OnButtonClick 等虚函数一览无余)
```

### 2.2 UI 控件与消息响应定位（ID 交叉引用法）
1. **获取控件 ID 范围**：
   在 UI 构建函数中（如 `0x005225FF`），寻找控件 ID 分配代码（如 `add eax, 0xc1c`，遍历 0..7 生成 `0xc1c` ~ `0xc23`）；
2. **搜索常量引用锁定回调**：
   在代码段中扫描该常量的机器码（如 `struct.pack('<I', 0xc1c)`），可直接命中按钮点击分发与处理函数（`OnButtonClick`）。

### 2.3 协议数据流“双向追踪法”
当界面表现与预期不符时（如点击进阶角色变回基础角色），沿以下闭环追踪：

```
[UI 点击] ──> [上报发包 C→S] ──> [服务端处理] ──> [回显确认 S→C] ──> [客户端本地应用]
```

1. **查发包入参源头**：
   - 搜 `push <opcode>; call COutPacket`（如 `push 0x57; call 0x64EE1C`）；
   - 向上检查传入 `Encode1` 的参数由谁计算得出；
   - **本次经验**：客户端在点击蓝妹妹（ID 10）后，主动调用了 `GetBaseCharacterBySkin(10)` 将其降级为基础角色 4 发包。**证明客户端发 4 属于原版网络协议规范，并非客户端 Bug**。
2. **查回包处理逻辑**：
   - 在 Stage 的 `OnPacket` 中找到该 Opcode 的解码函数（如 `0x004EFBF6` 处理 op 105）；
   - 查看收到的 bomber 写入了哪个槽位，随后调用了哪些渲染函数；
   - **本次经验**：槽位渲染函数 `0x4ef7fd` 内部检查了 `0x51969c`（判定 `8 <= bomber < 14`），若是高级角色则调用 `0x4731c4` 加载 3D 模型；若收到的是 4 则直接回退普通模型。这证明**服务端应答的必须是 10，客户端槽位才会生效高级模型**。

### 2.4 内存中的互逆双向映射表特征
进阶角色与基础角色在内存中存在成对的转换表（各 32 项 DWORD 数组）：
- `0x00B94100` (`BaseChar -> SkinChar`)：`[4] = 10` (蓝蓝 -> 蓝妹妹)
- `0x00B94180` (`SkinChar -> BaseChar`)：`[10] = 4` (蓝妹妹 -> 蓝蓝)
反汇编中见到 `mov eax, [eax*4 + 0x00B94100]` 或类似紧凑数组查表时，可直接读取内存 dump 出全量对应关系。
